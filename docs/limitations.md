# 免责与已知限制

## 免责

这个项目的每一个「能不能用」的问题，我都实测过；但**它对你机器上 AutoCAD 的每一次操作都是真实的**。

- 脚本会往**当前活动文档**里画东西，不做新建确认。跑之前请确认活动文档是你想改的那张。
- `cad_save` 无 `path` 参数时**就地覆盖**。没有任何撤销机制。
- `cad_send_command` 可以发送**任意** AutoCAD 原生命令——包括 `_.QUIT`、`_.ERASE ALL` 这类破坏性命令。它没有白名单，这是刻意的（封住它就没法应对未预料的情况），代价是**责任在使用方**。
- 建议：在用这个桥做任何批量操作之前，先备份图纸，或者开一张临时文档试。

软件按 MIT 协议「照原样」提供，不含任何担保。作者不对数据丢失、图纸损坏、工期延误或任何其他损失负责。

## 已知限制

### 平台

只有 Windows。COM 是 Windows 独有的机制，没有跨平台实现。

### AutoCAD 必须是桌面进程

插件默认**带界面**启动 AutoCAD。纯后台静默启动 COM 不稳定，这不是没尝试，是试过之后的选择。

V1.1 起桥支持**冷启动自动唤醒**：`acad.exe` 没在跑时，`cad_connect` 会经 COM
拉起它并等待就绪（实测强杀后约 15 秒恢复）。但拉起来的一定是带界面的桌面
进程，建议保持窗口打开。

### 模态弹窗会锁死一切

AutoCAD 弹出任何模态对话框（未保存提示、许可证、第三方插件更新提示）时，所有 COM 调用都会卡住，直到有人点掉。`cad_escape` 通过**文档的** `PostCommand` 发 ESC 能救一部分，但不是全部。

V1.1 起 `cad_status` 会报出 COM 线程已忙多久、队列积压多少；长期卡死可用
`cad_reconnect` 丢弃旧连接、换新 STA 工作线程重建。注意被卡住的旧线程是
daemon，不会被 `join` 等待——旧 COM 指针随 GC 回收。

### 串行

所有 COM 调用排队经过单个 STA 线程。并发调用安全，但不会更快——AutoCAD 本身单线程。

### 一个实例一个桥

桥绑定到「当前这个 AutoCAD 进程」。同时开两个 AutoCAD（比如两个不同版本的）会有问题：COM 的 `Dispatch` 只会拿到先注册的那个。

### 不做视觉验证

桥负责把意图变成实体。它不能告诉你画得对不对、好不好看。这需要截图然后看图，是另一个环节的事。

### 控制面板的像素渲染未经自动化验证

**这一条要说得准确一些。**

面板的**逻辑**有测试覆盖：

- `clienttest.mjs` 用假 Cordis 上下文跑 38 项断言——模块契约、slot 注册（`main` 的 key 与 `sidebar.panellist` 的 id 必须一致）、中英文字典键集完全一致、样式只用 `--dsw-alias-*` 主题 token、无硬编码颜色
- `selftest.mjs` 用真进程跑 9 步——起桥、探端口、读日志、存配置、停桥
- `watchdogtest.mjs` 验证崩溃重启、主动停止不重启、退避阶梯
- `findtest.mjs` 验证路径发现与配置迁移

面板的**外观**没有自动化验证。原因：DSH Web GUI 的访问令牌只存在于宿主进程内存（一个 `WeakMap`），不落盘、没有读取接口。拿不到令牌就没法从命令行打开页面截图做像素比对，而项目规范也禁止为了截图去绕鉴权或伪造 mock 页面。

所以：**界面结构、样式来源、slot 挂载点都被验证过，具体长什么样需要你自己点一下确认。** 如果你看到布局错乱，那是真问题，请开 issue 附截图。

### 标注对象没有完整重建

示例脚本里的 `part-3view.py` / `valve-3view.py` 用的是 `AddDimRotated` / `AddDimDiametric` 生成的**真标注对象**（不是画线冒充）。

V1.1 已把标注做成原生工具：线性、对齐、半径、直径、角度、坐标 6 种，外加
中文文字样式与国标标注样式；`cad_add_tolerance` 能生成形位公差框
（`AcDbFcf`）。仍**未实现**的：引线标注（leader）、表面粗糙度符号、焊接
符号，需要时用 `cad_send_command` 发原生命令。

### 3D 建模的边界（V1.3）

V1.3 已把 3D 做成原生工具：7 种原语、面域拉伸/旋转/扫掠（`AddExtrudedSolid`
/ `AddRevolvedSolid` / `AddExtrudedSolidAlongPath`）、布尔并交差、旋转、
剖切、截面、包围盒读取，外加 `cad_dimensions_to_3d` / `cad_profile_to_3d`
两句话推理。仍有边界：

- **无放样（Loft）、无曲面造型**。COM 全库没有 `Loft` / `Sweep` / `Fillet`
  / `Chamfer` 实体方法；倒角圆角走 `_.FILLETEDGE` / `_.CHAMFEREDGE` **命令**，
  是 fire-and-forget（异步、无法读回验证），需在 CAD 里目视确认。
- 2D→3D 推理只支持**单一闭合轮廓 + 厚度**（或长宽高 → box）。它不会从三
  视图反推复杂拓扑、台阶、孔位；「根据三视图自动推理立体结构」仍是 ROADMAP
  V2.0 的目标。
- 视觉样式（`VSCURRENT`）只能发命令、不能读回验证；视图方向用 `VIEWDIR`
  验证，但**渲染效果本身不做视觉检查**。
- `solid.MassProperties` 在本版本不可用，体积/质量校验走不通，`cad_solid_info`
  只给包围盒。

### 没有写入操作的撤销

桥没有实现事务或撤销栈。一次失败的批量操作可能留下半成品，需要手动清理（`cad_list_entities` 可以看现在有什么）。V1.2 起批量引擎对已打开的文档只复用、不重复 `Open`，但**仍不提供事务级回滚**。

### 批量引擎的边界（V1.2）

- 批量导出一次只处理一个文档视图，仍是**串行**（COM 单线程），不会更快。
- 连续 DXF/Wblock/PDF 导出后 AutoCAD 后台收尾会忙 2~5 秒；`cad_batch_convert`
  用加宽的 BUSY 重试窗口（12×0.6s）兜住，但**单个导出工具**仍用默认窗口，
  紧接着连续调用可能撞 BUSY，建议交给批量工具一次做完。
- PDF 打印依赖本机存在 `DWG To PDF.pc3` 打印机配置；没有它会失败并回显原因。
- DXF 导出必须用**无扩展名**的路径（AutoCAD 自己补 `.dxf`），这是 COM 实测行为；
  DWG 导出走 `Wblock`（`Export("DWG")` 会报「参数无效」）。
- 修剪没有 COM 实体方法，走 `doc.SendCommand("_.TRIM\n\n…\n")`，**异步**，
  命令发出后需给 CAD 一点时间；返回的是「命令已发送」而非「修剪已完成」的保证。

### V2.0 工业版的边界

- **合规自检是静态规则，不是 CAD 审图专家**：`cad_check_drawing_compliance`
  只读图元与系统变量，按 5 类规则（图层错误 / 标注不规范 / 未闭合轮廓 /
  重复线 / 碎线）给结论。它**不改图纸**、不做几何拓扑重建、不判断「这个尺寸
  设计得合不合理」。重复线判定用端点排序到 4 位小数，碎线阈值默认 1.0
  绘图单位——误报/漏报都可能，结论需人工复核。
- **「图纸反解析」是图元数据反解析，不是视觉识图**：按 Slogan「非图像识别」
  + 离线硬规则实现为读现有 DWG 的 `ModelSpace` 图元参数 + 制图规范，生成
  参数清单与可执行的 `CadBridge` 复刻脚本。**不做** OCR、不看渲染像素、
  不从图片/扫描件反推；复杂拓扑、放样曲面、三视图反推仍不在范围内。
  复刻脚本按图元逐条重放，不保证与原图的块依赖 / 外部参照 / 布局完全一致。
- **企业模板不做「按公司名自动匹配规范」**：`cad_read_drawing_standard` 能
  读出一张 .dwt 里真实的图层 / 文字样式 / 标注样式 / 线型 / 系统变量，
  `cad_load_template` 能按它开新图；但「自动挑出符合某公司制图制度的模板」
  需要企业自己维护一份规范库/映射表，当前不实现。模板目录由
  `LOCALROOTPREFIX + "Template"` 运行时解析；对不存在的 .dwt 路径，
  AutoCAD 会**静默建普通新图**，所以工具先 `os.path.isfile` 校验并显式拒绝。
- **工程日志是进程内内存缓冲，不是持久化审计数据库**：
  `ACTIVITY_LOG_CAPACITY=2000` 条环形缓冲，桥重启即清零；记录的是
  `_call` 层的工具动作（成败 / 耗时 / 线程），不含图纸内容、不联网、不上传。
  `cad_export_activity_report` 只是把当前缓冲导成 Markdown 快照；要长期
  留存需自己定时导出或接外部日志系统。
- **V1.4 国产 CAD 兼容（中望/浩辰）仍缺**：本机实测注册表 ProgID、三处
  Uninstall、常见安装目录均无任何中望/浩辰安装，没有 live 验证对象，
  因此 V2.0 先交付、V1.4 推迟到装了对应软件再补。

## 未实现但可能有用

按我自己的使用经验排序（V1.1 已把原第 1、3 项做掉，V1.2 已做批量导出与 BOM，V1.3 已做原生 3D 建模，V2.0 已做合规自检 / 模板 / 反解析 / 工程日志）：

1. **批量图元删除**——目前只能发 `_.ERASE` 命令
2. **视口与布局**——模型空间之外的图纸空间操作
3. **引线标注 / 表面粗糙度 / 焊接符号**
4. **放样 / 曲面造型 / 三视图反推复杂拓扑**——ROADMAP V2.0 的「AI 识图反向
   解析」按「非图像识别」实现为图元数据反解析，视觉/复杂拓扑反推仍留待后续
5. **国产 CAD 双接口兼容**（中望/浩辰）——见 [ROADMAP](ROADMAP.md) V1.4，
   本机未安装、无 live 验证对象，暂缓
